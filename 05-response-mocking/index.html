延迟模拟：100ms – 2000ms ​

慢接口是前端最常漏测的场景（loading 闪现、竞态、按钮连点）。MSW 有三种延迟写法：

ts
import { delay, HttpResponse } from "msw";

// 1) 精确延迟（毫秒）
await delay(1200);
return HttpResponse.json(data);

// 2) 拟真模式：按 MSW 内置的真实网络延迟分布随机等待
await delay();         // 等价于 await delay("real")
await delay("infinite"); // 永不返回（挂起请求，测试超时/取消逻辑）

// 3) 本教程做法：全局场景延迟，所有 handler 读取同一配置（100–2000 可调）
await delay(scenario.latencyMs);

v3 的 delay() 不再接收 { min, max } 对象：无参即拟真随机分布， 需要明确区间时（如本教程 100–2000ms 滑块）自行传入计算好的毫秒数。

下面的场景实验室与教程、两个示例共享同一份全局配置（存在 localStorage）： 拖动滑块在 100–2000ms 之间调节，保存后点"探测"对比实际等待时间。

建议的测试矩阵：100ms（快网）→ 300ms（典型 4G）→ 2000ms（弱网）， 分别检查 loading 态、防抖、请求竞态（旧响应覆盖新响应）与取消按钮。

错误状态注入 ​

场景实验室支持三种错误模式：

  • none：正常；
  • force：每个走 prelude() 的业务请求都返回 forceStatus（默认 500）；
  • random：约 25% 概率注入错误，用于发现"偶发失败"下的 UI 韧性问题。

切到 force + 状态码 503，保存后回到 第四章的控制台 发请求，会稳定收到 503；切回 none 即恢复。 这个设计演示了一个重要思想：场景配置本身也可以是一组 mock 端点（GET/PUT /api/scenario），控制面板因此无需与 MSW 运行时直接耦合。

http.get("*/api/users/:id", ({ params }) => {
  const user = db.users.find((u) => u.id === String(params.id));
  if (!user) return HttpResponse.json({ error: { code: "NOT_FOUND" } }, { status: 404 });
  return HttpResponse.json(user);
});
