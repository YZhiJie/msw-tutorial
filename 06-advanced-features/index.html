6.1 动态响应、数据持久化与鉴权流程 ​

基础 handler 返回的是静态常量，本章让 mock 变成一个"行为完整的假后端"：动态生成数据、跨刷新持久化、完整登录授权，以及请求间的依赖关系。

动态响应：请求决定一切 ​

ts
http.get("*/api/users", ({ request }) => {
  const url = new URL(request.url);
  const page = Number(url.searchParams.get("page") ?? 1);
  const pageSize = Number(url.searchParams.get("pageSize") ?? 20);
  const q = (url.searchParams.get("q") ?? "").toLowerCase();

  const filtered = db.users.filter(
    (u) => u.name.toLowerCase().includes(q) || u.email.toLowerCase().includes(q),
  );
  // 分页壳字段全仓库统一：data / page / pageSize / total / totalPages
  return HttpResponse.json(paginate(filtered, page, pageSize));
});

数据持久化：模拟数据库 CRUD ​

没有持久化的 mock 一刷新就"失忆"。本教程用 localStorage 仓库实现假数据库：

ts
const STORAGE_KEY = "msw-tutorial:db:v1";

class MockDb {
  users: User[] = [];
  posts: Post[] = [];

  constructor() {
    const saved = localStorage.getItem(STORAGE_KEY);
    if (saved) Object.assign(this, JSON.parse(saved));
    else this.seed();
    this.persist();
  }

  persist() {
    localStorage.setItem(STORAGE_KEY, JSON.stringify({ users: this.users, posts: this.posts }));
  }

  createUser(input: CreateUserInput) { /* ... */ this.persist(); }
  updateUser(id: string, patch: unknown) { /* ... */ this.persist(); }
  deleteUser(id: string) { /* ... */ this.persist(); }
  reset() { localStorage.removeItem(STORAGE_KEY); /* 重新 seed */ }
}

要点：

鉴权流程：登录、令牌轮换、守卫 ​

完整模拟 JWT 风格的双令牌认证（access token 短期 + refresh token 轮换）：

 登录 POST /api/auth/login {username,password}
      │ 成功 → { tokenPair: {accessToken, refreshToken, tokenType, expiresIn}, user }
      ▼
 业务请求 Authorization: Bearer <accessToken>
      │ access token 失效 → 401 + WWW-Authenticate
      ▼
 刷新 POST /api/auth/refresh {refreshToken}
      │ 成功 → 新的 tokenPair（refresh token 轮换，旧的立即失效）
      │ 重放旧 refreshToken → 401（模拟 reuse detection）
      ▼
 登出 POST /api/auth/logout → 200 {ok:true}

handler 侧的守卫就是一个读请求头的纯函数：

ts
function requireAuth(request: Request): AuthContext | HttpResponse {
  const header = request.headers.get("authorization") ?? "";
  const token = header.startsWith("Bearer ") ? header.slice(7) : null;
  if (!token) {
    return HttpResponse.json(
      { error: { code: "UNAUTHENTICATED", message: "缺少 Bearer 令牌" } },
      { status: 401, headers: { "WWW-Authenticate": "Bearer" } },
    );
  }
  const payload = verifyToken(token); // 本教程签发的是可解析的 mock JWT
  if (!payload) {
    return HttpResponse.json({ error: { code: "INVALID_TOKEN" } }, { status: 401 });
  }
  const user = db.users.find((u) => u.id === payload.sub);
  if (!user) return HttpResponse.json({ error: { code: "USER_NOT_FOUND" } }, { status: 401 });
  return { userId: user.id, role: user.role, user };
}

// handler 里一行接入
http.patch("*/api/users/:id", async ({ request }) => {
  const auth = requireAuth(request);
  if (!("userId" in auth)) return auth; // 守卫返回的 401 响应直接透传给客户端
  // ...放行后的业务逻辑
});

请求依赖关系 ​

请求 B 依赖请求 A 的结果，是真实应用的常态：

  1. 创建 → 读取：POST 返回 201 + Location，客户端直接 GET 该 Location；
  2. 登录 → 变更：GraphQL mutation 复用同一套 Bearer 守卫；
  3. 刷新 → 重试：客户端封装在 401 时自动 /api/auth/refresh 并重放原请求；
  4. 上传 → 下载：POST /api/upload 返回文件 id，GET /api/files/:id 取回元数据。

两个示例应用的 api/client.ts 实现了第 3 条的单例会话（React 用 useSyncExternalStore，Vue 用 Pinia store），可对照阅读。

错误状态模拟清单 ​

本教程覆盖的故障注入面：

  • 状态码：400 / 401 / 403 / 404 / 409 / 422 / 429 / 500 / 503 及任意 /api/status/:code；
  • 网络错误：HttpResponse.error()（fetch reject）；
  • 慢响应：100–2000ms 滑块与 delay("infinite") 挂起；
  • 概率错误：25% 随机失败；
  • WS 异常关闭：服务端发 4001（业务关闭）/ 1011（内部错误）。
