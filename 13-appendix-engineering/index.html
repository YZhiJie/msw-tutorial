13. 附录：工程化边界、可观测性与实时协议 ​

前十二章解决「怎么把 Mock 写得像真的」。这一章收口三件容易被忽略、但在团队协作里最痛的事：

  1. 边界：哪些包可以互相引用？Mock 会不会混进生产包？
  2. 可观测性：请求被 Mock 接住之后，怎么快速回答「刚才发生了什么」？
  3. 实时协议：WebSocket 的心跳、关闭码、断线重连如何约定，才能和真实后端对齐？

13.1 依赖边界：一张表管住所有 import ​

消费方允许从 contract 导入允许从 mocks 导入说明
React / Vue 示例类型、客户端、契约常量仅 @msw-tutorial/mocks/browser（devDependency）领域类型一律来自 contract；mocks 只在本地 Mock 模式动态加载
文档站类型、清单@msw-tutorial/mocks/browser页内交互实验室启动共享 worker
mocks 包类型、Schema、版本、客户端—handler 只依赖契约，不反向依赖任何应用
测试任意任意测试目录内可用 mocks/node 启动 setupServer

边界不能只写在文档里，要靠 lint 强制。eslint.config.js 中的真实规则：

13.3 实时协议：连接不是「打开就完事」 ​

WebSocket 的保真度不在「能发消息」，而在生命周期约定。本项目的聊天室协议：

text
客户端                          Mock 服务端
  │ ── 建立连接 ─────────────────▶ │  欢迎语（system）
  │ ◀───────────────────────────── │  广播「XX 加入」
  │ ── "ping" ───────────────────▶ │
  │ ◀───────────────────────────── │  { type: "pong", time }
  │ ◀───────────────────────────── │  每 5s 心跳 { type: "ping" }
  │ ── "close-me" ────────────────▶ │  关闭码 4001（自定义）
  │ ── "error-me" ────────────────▶ │  关闭码 1011（服务端错误）
  │ ── 网络断开 ──────────────────▶ │  广播「XX 离开」

约定要点：

项约定为什么重要
心跳服务端每 5 秒推 { type: "ping" }，客户端可回 ping 得 pong中间代理常在 60s 空闲后断链；有心跳才能提前发现
关闭码4001 表示「业务主动断开」，1011 表示服务端内部错误客户端据此决定「不再重连」还是「稍后重连」
重连指数退避 + 抖动，且 4001 不重连避免服务端故障时被客户端打成雪崩
顺序连接后先收到欢迎语，再参与广播客户端要在 open 前挂好 message 监听

一个最小可用的重连封装（可直接复制到前端）：

ts
type SocketOptions = { baseDelayMs?: number; maxDelayMs?: number };

export function connectWithBackoff(
  url: string,
  options: SocketOptions = {},
): { socket: WebSocket; stop: () => void } {
  const baseDelayMs = options.baseDelayMs ?? 500;
  const maxDelayMs = options.maxDelayMs ?? 5000;
  let attempt = 0;
  let stopped = false;
  let socket: WebSocket;

  const open = () => {
    socket = new WebSocket(url);

    socket.addEventListener("open", () => {
      attempt = 0; // 成功连接后重置退避
    });

    socket.addEventListener("close", (event) => {
      // 4001：服务端明确要求断开，不再重连
      if (stopped || event.code === 4001) return;
      const delay = Math.min(baseDelayMs * 2 ** attempt, maxDelayMs);
      attempt += 1;
      setTimeout(open, delay + Math.random() * 200); // 抖动，避免同时重连
    });
  };

  open();
  return {
    get socket() {
      return socket;
    },
    stop() {
      stopped = true;
      socket.close(1000, "客户端主动关闭");
    },
  };
}

13.4 生产边界：MSW 不该出现在用户浏览器里 ​

检查项正确做法反例
依赖类型mocks 放 devDependencies放 dependencies，生产安装时白白增大体积
加载时机只在 Mock 模式动态 import()顶层静态 import，生产包也包含 worker
启动条件runtimeConfig.mode === "mock" 才启动无条件启动，真实后端被拦截
worker 文件只在开发/演示环境部署把 mockServiceWorker.js 发布到生产
环境标识响应头 X-Mock: true联调时分不清真假数据

本项目示例的启动分支：

ts
if (runtimeConfig.mode === "mock") {
  const { startMockWorker } = await import("@msw-tutorial/mocks/browser");
  await startMockWorker();
}

13.6 练习 ​

  1. 给 /api/mock-events 加一个 kind=http|ws 过滤参数，并补一条测试。
  2. 把事件缓冲从 100 调到 500，思考：为什么不能无限增长？如果要做持久化，应该落在哪里？
  3. 用 connectWithBackoff 连接 /ws/chat，手动触发 error-me，观察 1011 是否会触发重连；再触发 close-me，确认 4001 不再重连。
  4. 在 Real 模式构建产物里搜索 mockServiceWorker 与 setupWorker，确认它们没有进入首屏包。

教程正文到此结束。回到任意一章的「练习」，都可以用 pnpm verify 作为最终验收：它同时检查类型、规范、行为、覆盖率、契约与构建。
