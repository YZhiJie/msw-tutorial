11. Mock 保真：用行为矩阵定义「像不像真实后端」 ​

第八章讲的是「字段和路径一致」，但真实后端还有一层更难对齐的东西：行为。

  • 同一个 GET 带 If-None-Match，真实后端返回 304，Mock 却返回 200；
  • 两个人同时改一条数据，真实后端用 If-Match 拦住丢更新，Mock 直接后写覆盖；
  • 上传 6MB 文件，真实后端 413，Mock 照单全收；
  • 连续请求 20 次，真实后端 429，Mock 永远 200。

这些差异不会让类型检查报错，却会让「本地全绿、联调爆炸」。

本章用一张行为矩阵把「Mock 应该像到什么程度」写死，然后逐条实现、逐条测试。

实现（packages/mocks/src/http.ts）：

ts
export function jsonWithEtag(
  request: Request,
  data: JsonBodyType,
  init: HttpResponseInit = {},
): Response {
  const etag = jsonEtag(data);
  const headers = new Headers(init.headers);
  headers.set("ETag", etag);

  const ifNoneMatch = request.headers.get("if-none-match");
  const matches =
    ifNoneMatch !== null &&
    ifNoneMatch.split(",").some((value) => value.trim() === etag);
  if (matches) return new HttpResponse(null, { status: 304, headers });

  return HttpResponse.json(data, { ...init, headers });
}

要点：

  • ETag 是内容哈希（FNV-1a），任意字段变化都会产生新值；
  • 304 必须没有 body，但仍保留 ETag；
  • Mock 统一设置了 Cache-Control: no-store，所以浏览器不会自动缓存。想练习条件请求，需要在客户端显式保存 ETag 并发送 If-None-Match；这也更接近「自己控制缓存」的教学场景。

行为约定：

请求结果
不带 If-Match兼容旧客户端，直接更新
If-Match: *只要资源存在就更新
If-Match 与当前 ETag 一致200，返回新 ETag
If-Match 过期412 PRECONDITION_FAILED，并返回当前 ETag

为什么不是 409？409 表示「业务冲突」（如邮箱重复）；412 专门表示「前提条件失败」（RFC 9110）。两者语义不同，日志与告警也应分开。

真实后端通常还会校验：

  • 文件名路径穿越（../../etc/passwd）→ 400；
  • 魔数（magic bytes）与声明的 MIME 不一致 → 415；
  • 分片上传、断点续传 → 需要额外的协议设计。

这些超出本教程的 Mock 边界，矩阵里不承诺。

实现要点：

  • key 默认 anonymous，可用 X-RateLimit-Key 覆盖，便于多租户/多用户演示；
  • 固定窗口：窗口到期自动重置，reset() 供测试与 /api/db/reset 清理；
  • 生产环境应使用 Redis 等分布式存储，Mock 只保证单进程语义可解释。

11.6 行为矩阵怎么维护 ​

  1. 新增一条行为时，先改矩阵（文档 + 测试名），再写实现；
  2. 每条行为至少一个自动化用例，见 packages/mocks/test/fidelity.test.ts；
  3. 明确写出「不承诺保真」的部分，防止读者误以为 Mock 能替代真实后端；
  4. 真实后端行为变化时，先改矩阵，再改 Mock，最后改文档——顺序不能反。

11.7 本章你要动手的事 ​

  1. 给 POST /api/posts 加 If-Match 支持（目前只有用户详情有 ETag）；
  2. 给列表接口加 Link 响应头（first/prev/next/last），并补测试；
  3. 把限流 key 改成「Authorization 令牌 + 路由」，观察不同用户互不影响；
  4. 打开两个终端同时 PATCH 同一个用户，用同一个 ETag，验证第二个请求收到 412。

11.8 常见坑 ​

坑后果规避
ETag 用随机值每次请求都 200，缓存失效用内容/版本号计算
304 带 body部分客户端解析失败304 必须无 body
把 412 当 409监控与重试策略混乱前提条件失败用 412
上传只校验前端绕过前端即可打爆存储服务端必须再校验
限流只写文档联调时压测直接打穿Mock 也实现 429 语义
